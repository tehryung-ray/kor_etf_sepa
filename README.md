[snp_sepa_mmt](https://github.com/tehryung-ray/snp_sepa_mmt)의 국내 ETF판입니다.
**규칙은 그대로, 대상만 바꿨습니다** — S&P 500 개별주 대신 **한국거래소에 상장된
ETF**를 매일 가중 모멘텀으로 줄 세우고, 상위 20개에 마크 미너비니의 SEPA 점검을
적용해 "모멘텀은 강한데 매수해도 되는 상품인가"를 판별합니다.

> **레버리지 · 인버스는 유니버스에서 제외합니다.** 배수·역방향 상품은 일간 복리
> 효과 때문에 추세추종 점수 체계가 의도대로 작동하지 않습니다. KRX 상품명 규칙상
> 해당 상품은 이름에 반드시 `레버리지` / `인버스` / 배수 표기(`2X` 등)가 들어가므로
> 이름 기준으로 걸러냅니다 (매 실행 약 100종목).

| | 하는 일 | 출처 |
|---|---|---|
| **가중 모멘텀** | 국내 ETF를 수익률 가중합으로 랭킹 → 상위 20 추림 | `snp momentum` 전략 |
| **SEPA 점검** | 그 20개가 미너비니 기준에 맞는지 125점 만점 채점 | `stock-screener-main` 전략 |

모멘텀 1위가 곧 매수 대상은 아닙니다. 실제로 대부분의 모멘텀 상위 종목은 SEPA에서
걸러집니다 — 그 **탈락 이유를 보는 것**이 이 페이지의 목적입니다.

## 원본과 달라진 곳

바뀐 것은 유니버스와 40점짜리 항목 하나뿐입니다. 나머지 85점과 판정 게이트는 원본과
동일합니다.

| | 원본 (S&P 500) | 이 저장소 (국내 ETF) |
|---|---|---|
| 유니버스 | Wikipedia S&P 500 구성종목 | 네이버 금융 ETF 목록 (레버리지·인버스 제외) |
| 시세 | yfinance | yfinance (`<종목코드>.KS`) |
| 벤치마크 | SPY | KOSPI 지수 (`^KS11`) |
| 40점 항목 | **펀더멘털** — 매출 15 · EPS 15 · 재고 10 | **펀드 품질** — 순자산 15 · 유동성 15 · 괴리율 10 |
| 나머지 85점 | 추세 40 · 손익비 15 · 상대강도 10 · 거래량 10 · 진입 5 · VCP 5 | ← 동일 |
| 매수 게이트 | Phase 2 · 템플릿 7/8 · SEPA 60점 | ← 동일 |

### 왜 펀더멘털 자리를 바꿨나

ETF에는 매출도 EPS도 재고도 없습니다. 원본 로직을 그대로 두면 20종목 전부가 "데이터
없음 → 중립 20점"을 받아 그 40점이 순위에 아무 정보도 주지 못합니다.

그래서 **같은 배점으로 같은 질문**을 던집니다. 원본이 펀더멘털에서 묻는 것은
"껍데기가 아니라 실체가 받쳐 주는가"입니다. ETF에서 그에 대응하는 것은:

| 항목 | 배점 | 환산 | 왜 |
|---|---|---|---|
| 순자산 규모 | 15 | 100억 → 0점, 1조 → 15점 (로그) | 규모가 작으면 상장폐지·괴리 위험 |
| 유동성 | 15 | 20일 평균 거래대금 1억 → 0점, 100억 → 15점 (로그) | 호가 스프레드가 수익을 먹는다 |
| NAV 괴리율 | 10 | 괴리 0% → 10점, ±1% 이상 → 0점 | 기초지수가 아니라 프리미엄을 사는 셈 |

원본의 중립 배점 방식을 그대로 쓰고 싶으면 `config.py`에서:

```python
FUND_QUALITY_MODE = "neutral"   # 전 종목에 20점 일괄 부여
```

### 유니버스 필터

ETF는 1,100종목이 넘고 상당수가 하루 몇 백만 원어치도 거래되지 않습니다. 실제로
매매가 불가능한 상품이 모멘텀 상위에 올라오는 것을 막기 위해 유동성 하한을 둡니다.
채점 규칙이 아니라 **유니버스 위생** 장치이며, 전부 `config.py`에서 조정합니다.

```python
MIN_AUM_EOK      = 300    # 순자산 300억원 이상
MIN_TURNOVER_EOK = 3      # 20일 평균 거래대금 3억원/일 이상
MIN_PRICE        = 1000   # 주가 1,000원 이상
```

여기에 Phase 분류에 필요한 **200거래일(약 1년) 이상 상장** 조건이 더해집니다.
전체 1,167종목 → 실제 분석 대상 약 440종목이 됩니다.

### 종목 링크

ETF 이름을 누르면 열리는 증권사 페이지입니다.

```python
LINK_PROVIDER = "toss"    # "toss" | "naver"
```

토스는 `tossinvest.com/stocks/<코드>` 형식으로, 숫자 코드와 2024년 이후 상장분의
영숫자 코드(`0008T0` 등)를 모두 해석합니다. 모바일에서는 앱으로 연결됩니다.

> 카카오페이증권은 개별 종목을 여는 공개 웹 주소가 없어 넣지 않았습니다.

## 화면 구성

**요약 바** — KOSPI 국면 / 매수 적격 수 / 템플릿 통과 수 / Phase 2 수 / 평균 SEPA

**랭킹 행** (한 줄에 종목 하나, 눌러서 펼침)

```
#  ETF                 분류      모멘텀  국면        템플릿      SEPA 점수      현재가
1  SOL 화장품TOP3플러스   업종·테마   5.49  P2 상승추세  ■■■■■■■■ 8/8  ███████░░ 91  18,545원
5  KODEX WTI원유선물(H)  원자재     4.48  P2 상승추세  ■■■■■■■■ 8/8  ██████░░░ 84  25,695원
```

- **템플릿 점 8개** — 미너비니 트렌드 템플릿 8개 조건. 채워진 칸이 통과.
- **SEPA 막대** — 125점 만점. 막대 위 세로선이 매수 임계선(60점)입니다.
- **초록 테두리 행** = 매수 적격.
- **ETF 이름(밑줄 + ↗)을 누르면** 토스증권 종목 페이지가 새 탭에서 열립니다.
  이름 밖 아무 곳이나 누르면 기존처럼 상세가 펼쳐집니다.

**펼친 상세**

- 펀드 정보 3단: 순자산 · 20일 평균 거래대금 · NAV 괴리율
- 매매 계획 4단: 현재가 · 손절가 · 1차 익절 · 최종 익절
- SEPA 점수 구성 7개 항목 막대
- 트렌드 템플릿 8개 조건 체크리스트 (어느 조건에서 걸렸는지)
- 채점 근거 전문 · 매수 적격 / 보류 사유
- 토스증권 · 네이버 금융 종목 페이지 링크

## 점수 체계

### 가중 모멘텀 (랭킹 기준)

```
score = 12×(1개월 수익률) + 4×(3개월) + 2×(6개월) + 1×(12개월)
```

최근 1개월에 가중치를 몰아 단기 주도 테마를 빠르게 포착합니다. 가중치는
`config.MOMENTUM_WEIGHTS`에서 조정합니다.

### SEPA 점수 (125점 만점)

| 항목 | 배점 | 내용 |
|---|---|---|
| 추세 구조 | 40 | 이동평균 이격도 · 기울기 · 돌파 · 과열 페널티 |
| **펀드 품질** | 40 | 순자산 15 · 유동성 15 · NAV 괴리율 10 |
| 손익비 | 15 | 2:1 미만 0점, 5:1 이상 만점 |
| 상대강도 | 10 | KOSPI 대비 20일 RS 기울기 |
| 거래량 | 10 | 상승일 거래량 / 하락일 거래량 |
| 진입 품질 | 5 | 52주 고가 근접도 (피벗 포인트) |
| VCP | 5 | 변동성 수축 패턴 품질 보너스 |

### 미너비니 트렌드 템플릿 8개 조건

1. 주가 > 150일선 · 200일선
2. 150일선 > 200일선
3. 200일선 1개월 이상 상승
4. 50일선 > 150일선
5. 주가 > 50일선
6. 52주 저가 대비 +30% 이상
7. 52주 고가 대비 −25% 이내
8. Phase 2 (확정 상승추세)

### 매수 적격 판정

세 조건을 **모두** 만족해야 합니다.

```
Phase 2  AND  템플릿 7/8 이상  AND  SEPA 60점 이상
```

> **원본과의 차이** — `stock-screener-main`의 `score_buy_signal()`은 Phase 2가
> 아니거나 템플릿 미달이면 즉시 0점을 반환합니다. 이 프로젝트는 원본 저장소와
> 동일하게 그 조기 반환을 걷어낸 진단용 채점기(`src/sepa.py`)를 씁니다. 모멘텀
> 상위 종목이 **어떤 국면에 있든 점수 내역을 항상 볼 수 있게** 하고 적격 여부만
> 따로 표시합니다.

## 실행

```bash
pip install -r requirements.txt
```

```bash
python run_daily.py
```

| 옵션 | 설명 |
|---|---|
| `--top N` | SEPA 분석 대상 상위 종목 수 (기본 20) |
| `--include-leverage` | 레버리지·인버스도 유니버스에 포함 (기본은 제외) |
| `--output PATH` | HTML 출력 경로 (기본 `docs/index.html`) |

종목 목록 1회 + 전 종목 시세 배치 다운로드 약 20초 = **30초 내외**로 끝납니다.
원본과 달리 종목별 재무 조회가 없어(ETF에는 재무제표가 없습니다) 더 빠릅니다.

## 데이터 소스

| 항목 | 출처 | 비고 |
|---|---|---|
| 종목 목록 · 순자산 · NAV | 네이버 금융 ETF 목록 API | 단일 요청으로 전 종목 |
| 일봉 OHLCV | yfinance (`<코드>.KS`) | 신형 영숫자 코드(`0008T0` 등)도 지원 |
| 벤치마크 | yfinance `^KS11` | KOSPI 종합지수 |
| 종목 링크 | `tossinvest.com/stocks/<코드>` | 숫자·영숫자 코드 모두 해석 |

> **pykrx를 쓰지 않는 이유** — KRX가 2025년 이후 목록·시세 API에 로그인을 요구하도록
> 바꿔서, 자격증명 없이 도는 GitHub Actions에서는 사용할 수 없습니다.

> **네이버 조회 실패 대비** — GitHub Actions 러너는 해외 IP라 네이버 요청이 막힐 수
> 있습니다. 성공한 목록은 매번 `data/etf_universe.json`에 스냅샷으로 저장되고, 조회가
> 실패하면 이 캐시로 폴백합니다. 이때 시세는 yfinance에서 정상적으로 받아오되
> 순자산·NAV 괴리율만 직전 값이 되며, **페이지 상단에 빨간 경고 배너가 뜹니다.**

## 자동 갱신

`.github/workflows/daily_scan.yml`이 **08:00 UTC** 에 실행됩니다. 한국시간으로
**같은 날 오후 5시**입니다.

```
15:30 KST  한국 증시 정규장 마감 (06:30 UTC)
17:00 KST  스캔 실행         ← 마감 1시간 30분 뒤, 당일 종가 확정 상태
17:00 KST  결과 수신 (같은 날)
```

한국은 서머타임이 없어 수신 시각은 연중 17시로 고정입니다. 월~금 실행이므로
**평일 저녁**에 갱신됩니다. 원본(미국장)과 달리 날짜가 넘어가지 않습니다.

워크플로가 하는 일:
1. 스캔 실행 → `docs/index.html` · `docs/guide.html` + `data/daily/latest.json` 생성
2. 변경이 있으면 커밋 & 푸시 → GitHub Pages 자동 재배포
3. 결과를 아티팩트로 90일 보관

수동 실행은 GitHub Actions 탭 → **Daily KRX ETF Momentum x SEPA Scan** → Run workflow
(상위 종목 수 지정 가능).

> **기준일 vs 실행일** — 커밋 메시지와 페이지 상단의 "기준일"은 **데이터의 실제
> 거래일**(`scan_date`)입니다. 실행 날짜가 아닙니다. 한국 휴장일에 돌면 직전 거래일
> 종가가 잡히므로 둘이 어긋날 수 있습니다.

## 파일 구조

```
kor_etf_sepa/
├── run_daily.py                    # 엔트리포인트
├── config.py                       # 전략 파라미터
├── requirements.txt
├── docs/index.html                 # GitHub Pages 출력물 (스크리너)
├── docs/guide.html                 # 사용법 안내 (초보자용)
├── data/daily/                     # 일자별 JSON 스냅샷
├── data/etf_universe.json          # 종목 목록 스냅샷 (네이버 장애 시 폴백)
├── .github/workflows/daily_scan.yml
└── src/
    ├── universe.py                 # ETF 목록 + 레버리지·인버스 제외 + 시세 배치 다운로드
    ├── momentum.py                 # 가중 모멘텀 점수 (원본과 동일)
    ├── phase_indicators.py         # Phase 분류 · 트렌드 템플릿 · VCP (원본과 동일)
    ├── sepa.py                     # SEPA 진단 채점기 (게이트 제거판)
    ├── etf_quality.py              # 펀드 품질 지표 — 원본 fundamentals.py 자리
    ├── report.py                   # HTML 리포트 생성
    └── guide.py                    # 사용법 페이지 생성
```

`momentum.py`와 `phase_indicators.py`는 원본에서 **한 줄도 고치지 않고** 가져왔습니다.
두 모듈 모두 비율 기반이라 통화·시장에 의존하지 않습니다.
